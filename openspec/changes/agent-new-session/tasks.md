Every slice follows `design.md`'s `## Global constraints`: the branch comparison base, the focused test commands, the `just format` and `just ci` slice gate, `just lint-linux` for a slice that adds or changes a `cfg` gate, and the changed-line coverage command. Test files are new topic files declared in their parent `tests.rs` and start with `use super::*;`, unless a case names an existing test to extend or reuse. A scenario with Examples is covered when every Examples row has its own case or its own assertion. Where a test calls an API this change adds, its RED run uses a stub of that API that keeps today's behavior, so the test fails on its assertion and not on compilation. Window tests build a `HerdrWindow` with `fixture_window` and a `crate::window::MockPeer` that advertises the methods the test needs, and read the requests the peer recorded, as the New Workspace tests in `crates/herdr-gpui/src/menu/new_workspace/tests.rs` do. herdr-client keeps one request in flight, so a test delivers each daemon answer twice: it answers the peer with `peer.respond(boot_id, id, response)`, which frees the connection for the next request, and it sets `live.dialog_response` and runs `update_workspace_dialog`, as `crates/herdr-gpui/src/worktree_scripts/tests/flow.rs:30-45` does. Tests advance time with `advance_clock`. A case that says no request was sent proves it with a sentinel after the action, modeled on `assert_no_request` (`crates/herdr-gpui/src/menu/new_workspace/tests.rs:177-197`). A lost connection reaches a test as the window sees it: `ClientEvent::RequestTimedOut` for a timeout, then `ClientEvent::Disconnected`. A test that needs the redial lives in `endpoint/lifecycle_tests/`. After the poll that sees the disconnection and the window update that follows it, the test sets the endpoint's `retry_at` to now and polls again, so the redial lands in a later poll and the generation changes as it does in the product. Tests that save shared settings or list and check real folders are gated `#[cfg(unix)]` test by test, as `title_model.rs`, `herdr_settings/tests.rs:17-19`, and the New Workspace folder tests are, because saving is Unix-only and the folder tests use Unix paths. A guard case, one whose bug only the new code can bring in, passes against today's behavior; run it once against the mutant its bug row names to see it fail. The guard cases are AN04's runs, Setting 02's values, Setting 07's Up and Down, Start 14, and the `start` label rows of Start 08. Expected strings come from the spec and design tables, never from the code under test.
